## 项目概览

料位仪需要把传感器的测量结果变成现场可读、上位机可取的数据。这个项目围绕这条链路，在 STC8H 单片机上集成激光测距、温湿度采集、本地显示和通信接口。

固件既支持按键触发测量，也实现了周期测量与倒计时；测量数据通过 LCD 展示，并映射到 Modbus 寄存器中，便于上位机读取。

[浏览完整源码与工程说明](https://github.com/C2418/C2418.github.io/tree/main/public/projects/level-meter/source) · [下载源码 ZIP](/projects/level-meter/level-meter-source.zip)

## 系统组成

| 层次 | 实现 |
| --- | --- |
| 主控 | STC8H，Keil 工程目标为 STC8H4K64TL Series，24 MHz 时钟配置 |
| 测量 | UART4 对接激光测距模块，DHT11 采集温湿度 |
| 交互 | 按键事件、ST7789 LCD 显示、背光超时 |
| 通信 | UART3 上的 Modbus RTU 从站，配合 NE2 模块连接网络侧 |
| 软件组织 | 1 ms 系统节拍、主循环调度、串口中断缓冲、命令队列 |

数据链路可以概括为：**激光模块 → 串口响应解析 → 测量数据寄存器 → LCD / 上位机**。按键和自动测量任务共用命令队列，统一发送测距指令与处理响应。

NE2 承担网络侧协议转换，MCU 固件实现的是 RTU 从站部分。模块的具体网络配置需要结合实际硬件确认。

## 实现要点

### 1. 将测量过程拆成命令与响应

测距模块通过串口收发命令，需要处理发送、等待响应、解析和超时。`cmd_queue.c` 将这些步骤组织成队列状态，按键任务和周期任务提交指令后，由主循环持续推进。

这样可以在等待模块响应期间继续处理其他应用任务。串口收发由中断与缓冲配合完成，应用层不必始终停在等待某一个字符的循环里。

### 2. 用系统节拍组织应用任务

`USER/main.c` 完成初始化，随后反复调用 `App_MainLoop()`。应用层负责 Modbus 请求、按键事件、命令队列、测距响应、温湿度采集和显示更新。

自动测量、倒计时和屏幕超时共用毫秒节拍。这里采用的是裸机轮询调度；DHT11 时序与显示操作仍有执行开销，不能把它等同于整个系统完全无阻塞。

### 3. 用寄存器统一通信数据

`modbus.c` 实现 RTU 帧处理、CRC16 校验与地址映射。3000–3006 对应设备地址、温湿度、量程、测量结果、百分比和错误标志；4000–4004 对应屏幕超时、测量间隔、倒计时与起止点参数。

这些是源码直接使用的协议地址。上位机工具对寄存器编号的显示方式可能不同，联调时需要确认基址和数据格式。

### 4. 将测量与现场显示结合

ST7789 驱动和 UI 模块负责显示测量相关信息；应用层还管理背光超时、活动时间和参数变化。温湿度与测距结果分别更新，再由显示与通信模块读取。

这部分体现的是从传感器接口到应用交互的集成：除了获得一个测量值，还需要处理数据何时更新、如何展示、如何被外部设备访问。

## 源码导航与复现

建议按以下顺序阅读：

1. `USER/main.c`：初始化与主循环入口。
2. `DRIVER/app.c`：任务组织与测量、显示流程。
3. `DRIVER/cmd_queue.c`、`DRIVER/uart.c`：命令状态与串口缓冲。
4. `DRIVER/modbus.c`：协议处理和寄存器映射。
5. `DRIVER/st7789.c`、`DRIVER/ui.c`：显示实现。

使用 Keil µVision/C51 打开 `RVDMK/LASER_STC.uvproj`，核对芯片支持、时钟和接线后编译。UART3/UART4 配置为 9600 bps，默认 RTU 从站地址为 1。完整步骤与寄存器概要见源码目录的 README。

本次提供全部 95 个原始文件，并保留原始编码和目录结构；另外补充一份项目 README。原理图、PCB、硬件照片与标定记录未包含在这份资料中。

## 当前边界与后续改进

静态阅读发现，Modbus 接收循环在判断每轮 20 字节上限之前就从 FIFO 取出字节。当数据积压时，可能多取走一个未处理字节。公开存档保留原实现，后续应调整判断顺序，并用长帧和连续帧验证。

料位换算及百分比还需要结合实际安装方式验证边界，测量精度、有效量程和长期运行表现应通过硬件测试给出，本文不填写未经测量的数字。
