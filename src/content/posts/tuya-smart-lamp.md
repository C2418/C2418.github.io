## 项目概览

- **项目开发时间：2025 年 9 月。**
- **源码公开整理：2026 年 9 月。** 此次上传是此前项目的源码归档与文档补充。

这个台灯项目围绕调光体验展开：让亮度和色温变化更平滑，同时支持旋钮、触摸与 App 操作，并在断网时保留本地控制路径。

应用基于 TuyaOS，在冷暖两路 PWM 输出之上组织灯光状态、渐变过程和多种输入。现有构建脚本面向 BK7231N，脚本中的原环境路径标注 TuyaOS 3.3.44；具体复现需要准备匹配的 SDK 与硬件。

## 功能与软件组成

| 功能 | 实现方式 |
| --- | --- |
| 亮度与色温 | 冷暖双路 PWM，通过两路占空比组合控制 |
| 渐变调光 | 独立渐变线程，根据起始值、目标值和时间推进输出 |
| 本地交互 | 旋转编码器、按键和触摸输入 |
| App 控制 | DP 指令解析、灯光状态修改与上报 |
| 离线使用 | 本地控制及在线、离线运行模式处理 |
| 状态管理 | 倒计时、掉电记忆、配网指示等相关逻辑 |

控制路径是：**App / 旋钮 / 触摸 → 灯光状态与控制协调 → 渐变计算 → 冷暖 PWM 输出**。网络状态和本地操作也参与控制流程，避免把应用简单写成“收到指令就改一次占空比”。

## 实现要点

### 1. 将目标亮度与渐变过程分开

`tuya_app_main.c` 保存当前输出与目标输出，由渐变任务逐步推进。代码包含平滑曲线及 gamma 处理，编码器调光路径还使用线性渐变，让不同输入方式可以有不同响应节奏。

源码中 PWM 频率配置为 10 kHz，渐变更新间隔为 20 ms。这些数值说明程序如何组织调光，不等于已经测得光输出线性度或响应时间；视觉效果仍需要结合灯珠和驱动电路验证。

### 2. 处理 App 与本地输入的协调

App 控制来自 DP 回调，旋钮和触摸来自本地输入，两者可能在同一段渐变过程中修改灯光状态。现有应用设置了硬件操作后的短时优先窗口，并组织在线、离线控制状态。

这类项目的难点不仅是让每个入口单独工作，还包括快速旋转时收到 App 指令、渐变中再次开关、网络变化时继续本地操作等组合场景。

### 3. 通过 DP 对接设备状态

`dp_process.c` 处理开关、亮度、色温和倒计时等数据点，并实现状态上报、掉电记忆等相关流程。核心 DP 包括 20（开关）、22（亮度）、23（色温）和 26（倒计时）。

源码中的亮度取值为 10–1000、色温控制值为 0–1000，后者是控制参数，并非以 K 为单位的实测色温。复现时，需要让涂鸦平台的产品功能定义与这些编号、类型和范围一致。

### 4. 保留断网时的本地操作

`offline_mode.c`、`encoder.c` 和 `touch.c` 组织本地操作路径。应用还包含配网指示和状态恢复逻辑，目的是让日常开关与调光不完全依赖 App。

断网、重新联网和掉电恢复涉及多个状态的衔接，需要组合测试；仅存在对应代码，并不能证明全部异常场景已经验证通过。

## 源码阅读与复现

建议先看 `src/tuya_app_main.c` 的灯光状态与渐变任务，再看 `src/dp_process.c` 的指令处理，最后结合 `encoder.c`、`touch.c` 和 `offline_mode.c` 理解本地输入。

仓库包含应用源码、`local.mk`、构建辅助脚本和随附第三方库。需要自行准备匹配的 TuyaOS SDK、工具链、产品配置与设备授权；源码目录 README 给出了集成步骤和硬件引脚核对项。

原始 quickstart 说明保留为 `README.tuya-demo.md`。厂商示例、SDK 接口与 `libqrencode` 等第三方内容保留原有来源和许可文件，不作为个人原创贡献。

## 当前边界与后续验证

现有渐变实现通过多项共享变量连接控制入口与工作线程。静态阅读发现，新渐变启动和旧渐变结束交错时存在状态覆盖风险；后续需要完善同步机制，并对 App 与旋钮快速交替操作进行压测。

本次公开整理保留业务实现，仅处理公开所需的标识脱敏与文档补充。历史修复记录中的结论未在此次复核，不填写未经实测的流畅度提升比例，也不把当前版本描述为量产验证版本。
